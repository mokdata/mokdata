## A project you can inspect

[Cancer Survival Predictor](https://github.com/mokdata/cancer-survival-predictor) explores two ways to ask a survival question. One predicts an outcome at a fixed horizon. The other estimates time to an event and accounts for observations that end before the outcome is known. The project uses synthetic data inspired by published breast cancer distributions. The README describes the models, evaluation and limits of the exercise.

In a separate **local MLOps project**, I served a scikit-learn model through FastAPI, validated inputs with Pydantic and ran the service in Docker. Automated tests, Cloud Run deployment and CI/CD are my next steps.

## Decisions from client work

- **When is clustering useful?** At Arkopharma I built five customer segments from purchase behaviour and delivered product recommendations to marketing. At the French Football Federation the clusters were difficult for marketing to interpret. I switched to rules based on customer profiles and licence history, then examined ticket and merchandise purchases by segment.
- **When should an AI idea move forward?** At Alstom I framed eight use cases and designed a weighted assessment for the AI team, covering data, performance, business risk, user validation, integration and observability. On TRAXX I built the Streamlit document-review interface on an existing backend.
- **What does an empty query result establish?** At Renault I investigated whether two files from a vehicle run could generate duplicate alerts. The BigQuery query found no match for the criterion and period examined. Testing the rule against a known event is the next step. I also contribute to the move from Spotfire to Streamlit and am taking over steering committee preparation.
